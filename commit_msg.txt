feat(build): add ELF build provenance attestation note

Goal
Add a second provenance channel to ZCC-linked ELF binaries:
.note.zcc.build (type 0x7cd) embedding SHA-256 hashes of the compiler,
linker, source manifest, and build policy used to produce the artifact.

Outcome
ELF executables linked with zld now carry two cryptographic provenance
notes — .note.zcc.tensor (model/GGUF) and .note.zcc.build (toolchain) —
both verified byte-identical across repeated builds.

Bugs caught mid-gate
- ELF64 verifier field offset bug: zcc_verify_build_note.py initially used
  sequential struct unpacks that misread e_shentsize/e_shnum from wrong
  ELF header byte offsets. Corrected to use exact absolute offsets per
  ELF64 spec (e_shentsize @ 58, e_shnum @ 60).

Hygiene / deferred
HYGIENE-001: Runtime verification deferred to Vector 8.4. Application
does not introspect its own build provenance at startup by design.
HYGIENE-002: .note.zcc.build and .note.zcc.tensor share PT_NOTE segment
pointer in write_output; multi-note segment plumbing deferred to Vector 8.4
if two simultaneous PT_NOTE entries are required.

Forensic notes
- Binary blob layout: 8 magic ("ZCC_BLD\0") + 4 schema_version + 4 flags
  + 4×32 SHA-256 hashes = 144 bytes. Zero JSON parsing in linker.
- Descriptor layout emitted into ELF: 136 bytes (8 header + 128 hashes).
  Full note section: 12 ELF note header + 4 name + 136 desc = 152 bytes.
- zld_link() expanded to 7 parameters; part5.c and zld.c updated.
- No mutation to existing .note.zcc.tensor or .zcc_tensor_attest semantics.
