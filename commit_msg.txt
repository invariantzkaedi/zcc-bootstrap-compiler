feat(linker): support multi-note PT_NOTE provenance segments

Goal
Replace the single-pointer note_sec with a spanning-range tracker so all
adjacent note sections (.note.zcc.tensor, .note.zcc.build) are covered by
one PT_NOTE program header entry instead of only the last-scanned section.

Outcome
A single PT_NOTE phdr now spans p_vaddr=note_first->vma to
note_last->vma+size, matching the standard single-phdr multi-note ELF
encoding. Both provenance channels are simultaneously visible to ELF
consumers without requiring a second phdr slot. HYGIENE-002 closed.

Forensic notes
- The span approach is correct per ELF ABI: a single PT_NOTE phdr may
  cover multiple SHT_NOTE sections when they are contiguous in the
  segment. GNU ld uses the same pattern.
- note_first tracks minimum VMA (note.zcc.tensor), note_last tracks
  maximum VMA (note.zcc.build). span_size = note_last->vma +
  note_last->size - note_first->vma.
- phdrs[4] array capacity unchanged — max phdr count stays 3
  (PT_LOAD RX + PT_LOAD RW + PT_NOTE).
- No change to tensor attestation or build attestation semantics.
